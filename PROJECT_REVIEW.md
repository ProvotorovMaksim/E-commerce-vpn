# Технический обзор · E-commerce VPN — API личного кабинета

Оценка для позиции Junior Python Developer / Integration Engineer. Основание — статический анализ исходников, сохранённых в Git на коммите `30d6ad8`. Выводы о сценариях отказа требуют проверки в рабочем окружении.

## Сильные стороны

Отдельные HTTP-клиенты локализуют контракты соседних сервисов. Модель владельцев позволяет обсуждать проверку доступа на уровне записи.

## Слабые стороны и архитектурные замечания

Операции с VPN и PostgreSQL выполняются по разным каналам. Сбой после успешного действия у провайдера и до локального commit может оставить расходящееся состояние. BackgroundTasks завязан на процесс API.

## Что проверить на демонстрации

Нужны получение реального статуса подписки, контрактные тесты внешних клиентов и восстановление после частичного сбоя.

## Вопросы для технического интервью

1. Что увидит клиент, если фоновая задача прервётся?
2. Как проверить доступ к чужому device_id?
3. Где хранить и как отзывать конфигурации устройств?
